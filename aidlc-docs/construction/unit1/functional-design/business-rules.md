# Business Rules — Unit 1: Frontend MVP

## BR-01: 社員フォーム必須フィールド

| フィールド      | 必須 | ルール                                |
|--------------|:---:|-------------------------------------|
| name         | Yes | 空文字不可                             |
| email        | Yes | 空文字不可 + メール形式（RFC 5322 簡易チェック）|
| department   | Yes | 空文字不可                             |
| position     | Yes | 空文字不可                             |
| employmentType | Yes | 有効な選択肢のみ（'full-time' / 'part-time' / 'contract' / 'intern'）|
| status       | Yes | 有効な選択肢のみ（'active' / 'leave' / 'retired'）|
| joinedAt     | Yes | YYYY-MM-DD 形式・未来日付不可           |
| skills       | No  | 空配列可                               |
| profile      | No  | 空文字可                               |
| avatarUrl    | No  | 空文字可                               |

## BR-02: メールアドレス重複チェック

- **登録時**: 既存社員と同じ `email` での登録は不可
- **編集時**: 自分以外の社員と同じ `email` への変更は不可
- **チェックタイミング**: フォーム送信時（バリデーション実行時）
- **エラーメッセージ**: 「このメールアドレスはすでに使用されています」
- **Phase 1**: `employees` Store 内でチェック（インメモリ）
- **Phase 2**: サーバーサイドで重複チェック（Node.js API）

## BR-03: 退職者の表示制御

- **デフォルト**: `status === 'retired'` の社員は一覧・統計に表示しない
- **表示切替**: ステータスフィルタのドロップダウンで「退職者を含む」を選択すると表示
- **権限**: 管理者のみ退職者フィルタを操作可能（Phase 2 で権限チェック追加。Phase 1 は UI のみ実装）
- **詳細ページ**: 退職者の詳細ページは URL 直接アクセスで閲覧可能（表示のみ）

## BR-04: ダッシュボード統計の集計スコープ

- **集計対象**: `status === 'active'` または `status === 'leave'` の社員のみ
- **除外**: `status === 'retired'` は集計から除外する
- **表示注記**: ダッシュボードに「在籍中の社員（active / 休業中）のみを集計しています」と明示する
- **部署別**: 同様に在籍中のみで部署別集計を行う

## BR-05: 退職処理ルール

- **実行者**: 管理者のみ（Phase 2 で権限チェック。Phase 1 は UI のみ）
- **操作**: 「退職処理」ボタン → 確認ダイアログ（「この社員を退職済みにしますか？」）→ `status: 'retired'` に更新
- **効果**: DB（Phase 1: Store）のデータは残る。一覧からは非表示（BR-03）
- **対象**: `status` が `'active'` または `'leave'` の社員のみ退職処理ボタンを表示する（すでに `'retired'` の場合はボタン非表示）

## BR-06: 完全削除ルール

- **実行者**: 管理者のみ（Phase 2 で権限チェック。Phase 1 は UI のみ）
- **操作**: 「完全削除」ボタン → 確認ダイアログ（「この操作は取り消せません。完全に削除しますか？」） → DB から物理削除
- **ダイアログ**: 退職処理とは別のダイアログ。危険アクションであることを赤文字等で強調する
- **削除後**: 社員一覧ページへリダイレクト

## BR-07: 入社日バリデーション

- **形式**: YYYY-MM-DD（`<input type="date">` が保証）
- **未来日付**: 本日より未来の日付は不可
- **エラーメッセージ**: 「入社日は本日以前の日付を入力してください」

## BR-08: 社員登録時の ID 生成

- **方式**: `crypto.randomUUID()` で UUID v4 を生成する
- **タイミング**: フォーム送信前（`createEmployee` AsyncThunk に渡す前）に生成する
- **Phase 2 以降**: ID 生成は Firestore の自動 ID に移行する

## BR-09: ナビゲーション権限（Phase 1 は表示のみ）

| メニュー項目 | Phase 1   | Phase 2（管理者） | Phase 2（一般社員）|
|-----------|:--------:|:---------------:|:---------------:|
| ダッシュボード | 表示      | 表示            | 表示            |
| 社員一覧    | 表示      | 表示            | 表示            |
| 社員登録    | 表示      | 表示            | 非表示          |

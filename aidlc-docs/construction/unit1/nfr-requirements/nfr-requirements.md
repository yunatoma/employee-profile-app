# NFR Requirements — Unit 1: Frontend MVP

## NFR-U1-01: パフォーマンス

| 指標                   | 要件                        |
|----------------------|---------------------------|
| 社員一覧 初期表示        | 3 秒以内（モックデータのため実質即時） |
| フォーム バリデーション  | 送信時に同期実行（UX 上の遅延なし） |
| フィルタ処理            | インメモリ処理のため即時          |
| バンドルサイズ           | 目標値なし（Phase 1 は規模小）    |
| コード分割              | 使用しない（Phase 2 以降で検討）   |

## NFR-U1-02: ブラウザサポート

| ブラウザ   | サポート範囲          |
|---------|------------------|
| Chrome  | 最新版 + 1世代前     |
| Firefox | 最新版 + 1世代前     |
| Safari  | 最新版 + 1世代前     |
| Edge    | 最新版 + 1世代前     |
| IE      | 対象外             |

**対応方針**: Vite のビルドターゲットを `browserslist` で指定する。
CSS は Tailwind CSS v4 が対応する範囲に依存。

## NFR-U1-03: アクセシビリティ

**目標レベル**: WCAG 2.1 AA

| 要件               | 詳細                                         |
|------------------|---------------------------------------------|
| セマンティック HTML  | `<button>`, `<label>`, `<input>` を適切に使う |
| aria 属性         | フォームエラー（`aria-describedby`）、ダイアログ（`role="dialog"`, `aria-modal`）|
| キーボード操作      | Tab でフォーカス移動、Enter / Space で操作可能   |
| カラーコントラスト   | テキストと背景のコントラスト比 4.5:1 以上         |
| スクリーンリーダー   | 主要な操作（登録・編集・削除）がスクリーンリーダーで操作可能 |
| フォームエラー通知   | エラー発生時に `aria-live` でスクリーンリーダーに通知|

## NFR-U1-04: セキュリティ（拡張ルール: Enabled）

| 要件              | 詳細                                           |
|----------------|----------------------------------------------|
| XSS 対策        | React の JSX 自動エスケープを活用（dangerouslySetInnerHTML 禁止）|
| 入力バリデーション | クライアントサイドでのバリデーション（業務ルールに基づく）      |
| エラーメッセージ  | 内部情報を含まないユーザーフレンドリーなメッセージのみ表示     |
| フォームセキュリティ | autocomplete 属性を適切に設定                   |

**注記**: Phase 1 はモックデータのためサーバーサイドセキュリティは対象外。Phase 2 で本格実装。

## NFR-U1-05: テスト（拡張ルール: PBT Enabled）

| カテゴリ                   | 要件                                             |
|--------------------------|------------------------------------------------|
| テストフレームワーク         | Vitest + @testing-library/react               |
| ビジネスロジック カバレッジ  | 100%（filterEmployees / validateEmployeeForm / dashboardStats）|
| PBT 適用対象              | filterEmployees（任意の入力で結果が一貫性を保つ）<br>validateEmployeeForm（無効値の境界テスト）<br>dashboardStats（集計結果の数学的整合性） |
| Redux Slice テスト         | employeeSlice の各 reducers / extraReducers     |
| コンポーネントテスト         | 重要なインタラクション（フォーム送信・ConfirmDialog）|
| スナップショットテスト        | 対象外（保守コストの観点から）                    |

**PBT 具体例**:
- `filterEmployees` : 任意の社員リストとフィルタ条件に対して、返却リストは入力リストの部分集合であること
- `dashboardStats` : totalActive === byStatus.active + byStatus.leave が常に成立すること
- `validateEmployeeForm` : 必須フィールドが空の場合は必ずエラーが返ること

## NFR-U1-06: 保守性

| 要件                 | 詳細                                          |
|--------------------|---------------------------------------------|
| 型安全               | TypeScript strict モード（noImplicitAny 等） |
| Lint               | ESLint（既存設定を維持）                        |
| コンポーネント設計     | 単一責任の原則に従う（1コンポーネント1責務）        |
| エラーハンドリング     | AsyncThunk の rejected ケースを全て処理する     |
| エラーバウンダリ       | 実装しない（AsyncThunk error ハンドリングで対応）  |

## NFR-U1-07: ユーザビリティ

| 要件                 | 詳細                                          |
|--------------------|---------------------------------------------|
| ローディング表示       | 非同期処理中は LoadingSpinner を表示する         |
| フォームエラー表示     | フィールド直下にインラインでエラーメッセージを表示する |
| 確認ダイアログ         | 破壊的操作（退職処理・完全削除）は必ず確認を求める  |
| リダイレクト           | 登録・保存・削除後に適切なページへ自動遷移する      |
| 空状態               | 社員が0件のとき「該当する社員が見つかりません」を表示 |
